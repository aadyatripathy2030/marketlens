Local tool — not an artifact

Video exporter

Renders an animation to a video file at full resolution. Recording happens in real time, so a 50-second clip takes 50 seconds. Leave the tab in the foreground while it runs — a backgrounded tab throttles the frame timer and the output stutters.

Ready.

1440 × 2160 is 2:3, not 9:16. TikTok, Reels and Shorts are all 9:16, so a 2:3 upload gets pillarboxed or centre-cropped. 1080 × 1920 is the native size and the safe default; 1440 × 2560 is the same shape at higher resolution. The 2:3 option is here because you asked for it — the animation letterboxes itself inside it rather than stretching.

Recording captures at 60fps. Output is .mp4 where Chrome supports it, falling back to .webm. A webm from MediaRecorder has no duration in its header, so Finder and QuickTime report it as a second or two even when every frame is there — mp4 avoids that.

Resolve cannot open the file this page downloads. Convert it first, and import the converted one.

Double-click tools/start-converter.command once and leave the window open. Every take you record from then on is sent straight to it the moment it finishes: it writes the recording and the Resolve-ready .mov together into ~/Movies/ChartGauge, and this page tells you when it is done. Nothing to remember and nothing to run afterwards.

Without it, takes download as usual and you convert them yourself: double-click tools/for-resolve.command, which converts every recording in Downloads that is not already done. Or from Terminal:
bash ~/stock-predictor/tools/for-resolve.command

The converter is handed each file by name rather than watching a folder, because a background job on macOS is not allowed to list ~/Downloads — it can read and write a path it is given, but ls on that folder returns nothing, so anything watching there always concludes there is nothing new.

What is wrong with the raw recording, read box by box out of a real one: MediaRecorder writes a fragmented container — ftyp, an empty moov, then moof/mdat repeating — whose sample table holds zero entries, so the header claims about a second for a thirty-five second clip. Every frame also carries its own duration (variable frame rate) at a non-standard nominal 29.02fps, and there is no audio track at all. Remuxing cannot fix frame timing, so the script decodes and re-encodes onto an exact 1/60s grid and adds a silent track.

It writes ProRes 422 in a QuickTime .mov, not H.264 in an mp4. Resolve decodes ProRes on every build and platform; an H.264 mp4 imports on one machine and fails on the next. The cost is disk space — roughly 640 MB for 35 seconds at 1440×2560 — which is the right trade for a file that opens every time. Add h264 as the last argument if you need the small one. It uses AVFoundation, which ships with macOS, so there is nothing to install. TikTok, Instagram and QuickTime all take the download as it comes; only Resolve needs this.

If you would rather use ffmpeg:
ffmpeg -i in.mp4 -c:v prores_ks -profile:v 2 -r 60 -vsync cfr out.mov
